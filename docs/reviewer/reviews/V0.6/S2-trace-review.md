# V0.6/S2 直接归因取证审查计划

Draft / 仅规划，2026-10-31。依据[取证设计](../../../leader/designs/V0.6/S2-trace-design.md)，后续用户明确启动后执行；本文件不是独立验收结果。

| 验收项 | 独立验证 | 失败/阻塞判定 |
|---|---|---|
| AC1 行为和保护 | 审查Gateway观察点不修改决策；U/O关闭路径无记录/额外时钟工作；L4补丁仅在自有隔离副本；源码hash、Release回归、相关TCP测试和资源回收 | 行为变化/来源不明/泄漏为FAIL，不带病采样 |
| AC2 取证可信度 | 自有构建与反序矩阵，先低档U/O/T三重复；检查CPU成本分母、成功分位、drop/证据预留、独占输出和首错保留 | 不满足设计开销门槛则BLOCKED，不追加样本或改阈值 |
| AC3 直接关联 | 独立解析原始ID、双端四元组、进程与连接代数/生命周期；验证端口复用、探针、未识别HTTP就被拒绝、部分失败、歧义以及阶段边界 | 不能按时间或FD猜测；关联覆盖不足/主因比例不足时不批准主要因果结论 |
| AC4 优化交接 | 对照高档U/T干扰门槛和直接分支证据，区分接入额度、关闭等待、finished待清理和L4传播错误；核查单项候选的机制与回退 | 配额触发或低CPU利用率本身不足以批准代码优化；证据不足则S2仍BLOCKED |

独立自有路径build-local/reviewer/v0.6-s2-trace，禁止和Builder并行压力。每角色最多18cell/1200秒/4GiB，性能与负控分母分开，不重启账本。Reviewer独立Release回归、诊断测试和L4 TCP相关测试，复核Builder的ASan+UBSan证据；只在前置通过后反序采集。工具/源码身份、低档门槛及高档解释边界均按设计原值执行，不在报告里另定新门槛。

报告分别判定：观察设施正确性、开销可接受性、直接归因是否成立、S2产品优化入口；有效负面诊断可收口，但不得声称已确认主因、已提速或最大容量。报告路径docs/reviewer/reports/V0.6/S2-trace-report-001.md，保留原始证据SHA及未验证范围。
