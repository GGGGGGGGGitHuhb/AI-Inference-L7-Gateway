历史 S1 的 24 项客户端/后端 phase 计数及输入 hash、12 项 L4 完整日志关闭原因/errno/字节和 accepted=closed 已独立复算，见 `history24-verification.json`、`history-l4-verification.json`。旧 L3840 六次传输失败 58643 个 ID 均不在后端完整请求收件集合，已连接失败生命周期中位数约 4.7–5.3ms；未修改或重新采集 S1。

新取证汇总与自有 12 项已审计 raw 结果逐 phase、错误类型、后端收件和输入 hash 一致；Builder 部分与其报告/取证汇总核对，未冒称再独立全量重算 Builder 新 raw。双方完整分母 **1843200 = 1509653 成功达标 + 330437 传输失败 + 3110 漏发**；传输失败为 330307 零响应 EOF、130 零响应 ECONNRESET。全部传输失败均未进入后端完整请求收件集合；M1 也有 2315 个同型失败，L 条件共 328122 个，因此不能认定为 L4 代码独有故障。

后端只有完整读取 HTTP 并解析 ID 后才形成身份记录，这不是包级“任何字节未到达”的证明。独立核对自有 15 个 backend-summary：accepts=requests，empty/rejected 均零，与 Leader 双方 30 实例摘要一致，见 `forensics-verification.json`。L4 日志无 HTTP ID，未将会话号或相近时间强行关联到请求；SO_ERROR/shutdown errno 可以由对端关闭传导，不能证明起因。

Gateway 接入达到 maxConnections 或预约失败时直接关闭已接受 socket，是与现象相容的源码候选；没有直接分支计数，不能认定它解释了全部失败。下一最小取证应记录接入拒绝原因、活动/已完成待回收会话及 L4 关闭侧/阶段，并验证取证开销。当前没有证据支持进入多 Worker 等产品架构优化。
