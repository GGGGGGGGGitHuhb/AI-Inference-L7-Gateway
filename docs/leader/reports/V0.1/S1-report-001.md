### 选型理由

- 选择 llhttp 作为字节解析器，保持现有 epoll 方向；不把 HTTP 协议处理与另一套异步运行时一起引入。Boost.Beast 也是可行替代，但本阶段不增加该依赖集合。
- 选择 nlohmann/json 的 SAX 校验以限制状态并避免完整 DOM 副本；采用自己的受限字段契约，不默认透传所有模型参数。
- 原 Server 的低层组件依赖较小，适合固定快照迁入；其服务层和 L4LB 完整会话运行时会带入多余职责。
- 首版接受非流式文本，响应采用有界完整正文规范化；V0.2 再增加持续转发与背压，不把 V0.1 的响应正文上限套在长 SSE 流上。
