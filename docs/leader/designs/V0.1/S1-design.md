## 5. V0.1 API 契约

S1 实现离线校验及错误分类；表内 HTTP 错误在 S2 才通过 Gateway 发送。错误正文格式固定为 `{"error":{"code":"稳定英文标识","message":"简明原因"}}`，不回显用户正文或凭据。

| 输入 | 支持范围与错误 |
| --- | --- |
| 路径与方法 | 精确 `POST /v1/chat/completions`，不带 query；其他路径 404，已知路径其他方法 405 并带 `Allow: POST` |
| JSON 根 | UTF-8 对象；无注释、无尾随非空白字节、无重复对象键；不符合为 400 |
| `model` | 必填非空字符串，UTF-8 字节长不超过 256；S1 只提取，不查实例映射 |
| `messages` | 必填，1—256 个对象；每项只含 `role`、`content`，前者取 system/user/assistant，后者为字符串 |
| `stream` | 缺省或 false；true 返回 400 `unsupported_stream`，流式支持从 V0.2 开始 |
| `n` | 缺省或整数 1；其他值拒绝 |
| `max_tokens` | 可选整数 1—8192；为首版实验限制，不承诺适配所有模型上下文 |
| `temperature` | 可选有限数值 0—2 |
| 其他字段 | 400 `unsupported_field`；不支持工具调用、图像、音频、多结果或任意扩展透传 |

校验成功保留原始 JSON 字节，包括空白，不重新序列化 prompt。HTTP dechunk 后得到正文，再验证并规范化长度；`model` 等少量元数据单独持有。

响应正文为不透明字节，不在网关做模型输出转换。V0.1 只接受无压缩、非 `text/event-stream` 的最终响应；200、4xx、5xx 等最终状态在协议合法时保留。204/304 按无正文规则处理；不把错误状态的正文当作成功生成结果。

## 6. HTTP 支持矩阵与边界

采用 HTTP/1.1 严格语法，不开启 llhttp 的宽松模式。处理顺序为语法/大小/定界校验，再做 API 校验；畸形输入不会因路径错误绕过长度检查。

| 场景 | 请求侧 | 响应侧 |
| --- | --- | --- |
| 版本 | 非 1.1 为 505，无法解析的起始行为 400 | 非 1.1 为 502 |
| Host | 恰好一个非空 Host，否则 400；发往上游时由配置的 authority 重建 | 不用于后端选择 |
| Content-Length | 单个合法十进制长度；重复或列表形式即使相同也拒绝 | 同样严格；非法为 502 |
| Transfer-Encoding | 仅单个 `chunked`，可含合法大小写/空白；空值、其他编码、重复或与 CL 共存为 400 | 同规则，非法为 502 |
| 无长度 | POST 无 CL/TE 返回 411；零长度正文最终因 JSON 无效返回 400 | 允许 EOF 定界；只有收到合法 EOF 才完整，不能复用该连接 |
| chunked | 增量解码，终块完整；扩展仅校验语法并忽略 | 同规则；不把中途断开当成完整终块 |
| trailers | 非空 trailer 或非空 Trailer 声明不支持，400 | 非空 trailer 或非空 Trailer 声明不支持，502；不得并入普通头 |
| Expect | 任意值返回 417，在等待正文前作出决定 | 100/102/103 等合法非 101 的 1xx 可跳过，最多 8 个，之后必须有最终响应；101 为 502 |
| Content-Type | 必须为 application/json，可带 charset=utf-8；其他为 415 | 识别并拒绝 text/event-stream；其余正文不解码 |
| Content-Encoding | 缺省或 identity；其他为 415 | 缺省或 identity；其他为 502 |
| 升级/隧道 | CONNECT、Upgrade 不支持，400 | 101/升级不支持，502 |
| 消息尾部剩余字节 | 适配层报告本消息消费量，把剩余字节留给调用方 | 同左；不能吞掉下一消息或自动归池 |

请求缺少/错误类型的字段、无效 UTF-8、重复 JSON 键、超深结构统一为 400 `invalid_request`；超正文预算为 413；超头部预算为 431；响应任何协议/容量错误映射为 502。llhttp 的底层错误名保留在内部分类，不作为稳定外部错误代码。

规范化时移除 `Connection`、其列举的逐跳字段、`Keep-Alive`、`Proxy-Connection`、`TE`、`Trailer`、`Transfer-Encoding`、`Upgrade` 和代理认证头。Connection 若提名 Host、Content-Length、Content-Type 或 Content-Encoding 等本契约必需语义字段，拒绝而非静默删除。完整正文转发重新生成唯一 Content-Length，追加本跳 `Via: 1.1 ai-inference-gateway`；原 Via 合法时保留。

首版不代理客户端 Authorization，后端认证不在 V0.1 范围。生成头只能使用已校验字段和受控配置，禁止 CR/LF 注入。普通端到端头按顺序保留，不能把所有重复头无条件合并。

S1 解析器一次只交付一条消息；完成时暂停并准确报告消费字节。`NeedMore`、`Complete`、`Rejected` 是建议结果语义，具体符合 C++ 规范的类型由 Builder 定义。S2 使用 Connection: close；S3 设计顺序 keep-alive 与流水线限制，S1 不提前决定网络调度行为。

### 容量默认值

以下为协议基础测试及后续首版的保守默认值，不是性能承诺。等于上限允许，超出拒绝；数值配置化由 S2 设计处理。

- 起始行 4 KiB；每组起始行加头部原始字节合计 16 KiB、100 个头字段；累计 1xx 头部也受独立 128 KiB 总预算限制。
- 请求解码正文 1 MiB，单条请求线上的总输入预算 4 MiB；非流式响应解码正文 4 MiB，总输入预算 8 MiB。消费到消息边界为止计量，不能把同批下一消息误计入本条。
- 单个 chunk 大小行（含扩展）最多 1 KiB；非终结 chunk 最多 65,536 个。请求编码开销超预算按 413，响应按 502。
- JSON 嵌套深度最多 32，所有对象键和数组元素合计最多 8,192 项；达到上限拒绝下一项。重复键检查使用有界键集合，按对象作用域区分，不能把不同 message 对象同名键误判重复。
- 整体报文有界并不等于进程 RSS 固定。本阶段验证单解析器预算；全局连接与缓冲预算属于 S2/V0.2，不能据此声称并发内存已受控。

## 7. 接口组织、所有权和调用流

- `src/http/` 持有每个解析器实例、其持久 settings、头/正文预算及状态。通过具名 C trampoline 接回 C++ 实例；不得让 C++ 异常跨 C 回调边界，内部异常转为明确失败并保证对象可销毁。
- `src/gateway/` 中仅放文本请求校验与元数据类型，不放连接或会话运行时。SAX 回调提取所需元数据并校验类型，使用有界状态栈。
- `src/base/`、`src/net/`、`src/timer/` 只持有迁入组件，不反向依赖 HTTP 或推理语义。
- 调用顺序：测试/调用方送入字节 → HTTP 严格解析与预算 → 请求 JSON 校验 → 规范化报文输出 → 显式结果。响应路径不经过请求 JSON 验证。
- 输入视图仅在一次调用期间有效；跨调用保存的头/正文必须有所有者。Buffer 修改可能使视图失效，消费前确保接收方已复制或取得所有权。
- settings、回调目标和解析器的寿命顺序必须固定；重置不得保留上一请求元数据。错误后不继续解释剩余数据为新请求，调用方需销毁或显式重新初始化。
- 必需回调装配完成才允许解析。回调 setter、具名处理函数、返回状态、成员命名和文件组织遵循 `personal-cpp-standards`；第三方回调签名和生成文件使用接口例外。
