## 触发与必须修正

F-001：原M2将合法charge>4096的拒绝写作queue_full。源码AdmissionController::enqueueRequest先count再byte检查；ProxySession分别映射503 queue_full与503 queue_bytes_exceeded。M2检查时只有两条活动请求、没有等待者，因此应为**503 queue_bytes_exceeded**，不是count拒绝。不得改产品匹配原文错误。

M2固定五条：M2-01/02为两个已确认活动且受门闩控制的a流；M2-03为合法请求、逻辑charge>4096，等待队列count=0，验证503 queue_bytes_exceeded且未连接上游；M2-04为小请求入队，明确等待至504 queue_timeout；随后放行01/02并排空，M2-05新a成功。结果仍3成功/1bytes拒绝/1排队超时。大请求满足原HTTP/JSON/请求体约束；charge按现有公式计算，不能用非法请求触发400冒充byte检查。

F-002：原M4“下一a全不可用503”及随后“两个摘除期限前确认503”可能误读为新增请求。现以以下唯一八条正式HTTP请求替换M4叙述，所有路由、冷却和等待状态确认均为host只读观察，不增加HTTP attempt：

| ID | 操作与门槛 | 唯一期望 |
| --- | --- | --- |
| M4-01 | a请求，先确认选中a1并收到首content，暂不发坏chunk | 与02/03建立组合后再注入坏chunk；已提交响应截断，1次后端失败，不补正常终止/第二头 |
| M4-02 | b请求，确认b1活跃，保留门闩 | 独立合法正文完整成功，不受a1失败影响 |
| M4-03 | a请求，在01/02均活跃时确认Waiting，然后触发01坏chunk | 观察a1摘除及该请求出队选中a2；放行02/03并确认完成，成功 |
| M4-04 | 关闭本角色a2监听及其所有已有连接，确认无活连接可复用、a1仍在摘除冷却期；发a请求 | 目标a2连接失败，502 upstream_error；确认a2也摘除，1次后端失败 |

| M4-08 | 新b请求 | 完整成功，模型隔离保持 |

07前启用a2监听避免选择已冷却但仍关闭的a2造成无关失败；实际目标与健康状态如实记录。不得修改Router产品选择策略或直接写入产品健康状态。正常成功总数为02/03/06/07/08共5；失败01/04共2；拒绝05共1，合计8。

1000ms冷却与500ms队列期限保持。门闩控制须及时推进；若观察发现预期时窗已错过，本attempt/run保留为未满足，不补请求、更换分类或延长配置通过。06若a2的冷却也已到期，试探必须以实际选中a1为通过前提；必要通过模拟监听恢复a2不能把a2成功冒充a1恢复。先读状态再发请求的少量竞态属于必须报告的门槛，不能依赖未记录的sleep或RR序号。
