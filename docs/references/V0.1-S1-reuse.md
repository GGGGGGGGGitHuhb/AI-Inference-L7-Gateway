## 新增适配层的边界

历史说明（2026-10-18）：下述扩展校验发现记录初次实现；当前已按 [返工 001](../leader/reworks/rework-001.md) 改为完整大小行前置有界校验，并经 [Reviewer 002](../reviewer/reports/V0.1/S1-report-002.md) 验收。此澄清不改变上表迁入组件、固定来源或机器清单。

- HttpParser 持有 llhttp settings 和 parser，禁止复制/移动。逐字节执行以准确计量预算和消费量，完成后暂停。该实现优先验证正确性，未给出吞吐性能保证。
- llhttp 9.4.3 在未启用 lenient 模式时仍接受 `1;=x` 的空扩展名。初次自测发现后，在自有层增加有界 chunk 扩展语法校验；第三方生成源码保持原样。
- 保留原始正文，JSON 使用 SAX；语义验证与预算同时进行，重复键按对象作用域区分。合法 API 的自然最大深度为 3，默认深度 32 与 8192 项边界通过含未知字段的结构隔离验证（未超限为 unsupported_field，超限为 invalid_request）。
- HTTP 解析完成不等于 API 合法：调用方依次检查 ParseResult、validateTextRequest，再调用 normalizeMessage。normalizeMessage 接受已解析消息，不能用于任意手工构造的未校验头。
- 204/304 无正文；规范化不生成 Content-Length，避免把 304 的表示长度误写成实体正文。其他完整消息由解码正文长度重建唯一 Content-Length。
- 请求错误用 serializeError 输出；405 附 Allow: POST。上游 authority 必须是受控配置，规范化额外拒绝控制字符、空白及路径分隔符。
- 所有 C 回调具名并 catch(...)，异常变成不分配内存的 Rejected；测试程序替换分配器验证 C 回调内失败路径，不在产品加入故障开关。
