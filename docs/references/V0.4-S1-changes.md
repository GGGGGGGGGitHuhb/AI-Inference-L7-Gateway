# V0.4/S1 性能工具来源与职责

起点44266088f5d93880983eb58a27117b796af7075b；初次实施0/2。只新增tests/experiments、必要CMake目标和Builder文档，不改产品/旧P1/MVP工具及第三方。

- Plan.py：Approved 57cell/7590ID、交错顺序、配置/SLO/请求序列，正式前hash。
- Client.py：只读复用旧WireResponse解帧契约，按本阶段字段记录增量HTTP/SSE/hash与有界摘要。A/P1原1024JSON、B/P1原4MiB SSE字节在短控逐字比对，H/Q独立1024SSE。
- Worker.py：有界线程/IPC、闭环/均匀开环、50ms迟到和128活动槽，不写受管run文件；T双进程各C4共享同一绝对t0。
- Backend.py：标准库独立合成进程，逐请求20/100ms异质延迟及第四长乘4，无隐含CPU模型；每cell≤256摘要、NODELAY实际getsockopt、accept/request与预热快照。
- RuntimeHost.cpp：沿既有friend测试访问，链接同gateway_runtime，精简IPC而不写全历史；只读Session转移和资源，仍调用原onCleanup。唯一新增C++，命名/职责/回调/空行按个人规范。
- Infrastructure.py：父端有界IPC、资源观察/排空、固定本地资产archive/server/model/库/许可校验。
- Budget.py：借鉴S3已经独立验收的分区/写前计费/直接路径预留思想，在新模块使用本阶段512+448+64MiB、512KiB直接路径。没有导入/改变旧Budget.ACTIVE或默认值；子进程不持有另一份受管预算。
- RunExperiments.py：一次完整矩阵、当前cell finally与未开始全计划闭合、正式网关/只读host分路径、三次真实generation任务边界及有限清理。
- Statistics.py / Analyze.py：时钟/终态/ID守恒、scheduled与发送后两种时延、冻结SLO/goodput、nearest-rank门槛、各重复与成对有效性；不把负面结果自动当工具失败，也不把工具缺陷当有效负面结果。
- DetectorTests.py：只运行离线/loopback短控，不自动启动模型或完整矩阵。覆盖真实部分200错误、五类预算非零、双发压中断、future异常、开环迟到/槽满、时钟/分类/SLO/分位、错误资产/端口冲突、资源/背压等。

真实R-P观测按Leader实施澄清：保持正式程序不变，按每后端唯一generation task开始/释放/timing在预热前、预热后、正式后三边界校验；保存metrics原文但不把token/HTTP访问/slot数当生成请求数，不宣称逐ID后端目标。共享CPU、有限样本、观察和发压开销保持明确边界。
